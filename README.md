# Практична робота №3 — HTML-форми LUME

LUME — навчальний магазин смарт-речей для дому: освітлення, живлення, керування та датчиків. Проєкт продовжує [практичну №2](https://github.com/aemuw/practical-02-lume). Основна предметна сутність — товар каталогу.

## Структура й запуск

```text
practical-03-lume/
├── index.html
├── login.html
├── register.html
├── product-form.html
├── README.md
├── WALKTHROUGH.md
├── CHECKS.md
├── REPORT-DRAFT.md
├── evidence/
└── .gitignore
```

Відкрийте `index.html` у браузері та перейдіть до потрібної форми через меню. Залежності й термінал не потрібні. Реалізація — лише HTML, без CSS, JavaScript і Backend. Зображення не додавалися: форма не потребує графіки, а головна сторінка продовжує HTML-структуру практичної №2.

## Форми, GET/POST і майбутні маршрути

| Сторінка | Метод | action | Призначення та обґрунтування |
|---|---|---|---|
| index.html | GET | index.html | Пошук: параметр `search` з’являється в URL, його можна зберегти як закладку. Фільтрації каталогу ще немає. |
| login.html | POST | api/login | Передати облікові дані для майбутнього входу. Пароль не має опинятися в query string. |
| register.html | POST | api/register | Створити обліковий запис у майбутньому; операція змінює дані. |
| product-form.html | POST | api/products | Створити товар каталогу у майбутньому; операція змінює дані. |

Маршрути записано **відносно папки проєкту**: після публікації в підкаталозі GitHub Pages `api/login` також буде всередині цього підкаталогу. Це умовні майбутні маршрути, а не готові API.

GET кодує дані в URL. POST передає їх у тілі запиту; сам POST не шифрує дані. Передавання захищає HTTPS. GitHub Pages обслуговує статичні файли й не реалізує ці POST-маршрути. При відкритті через `file://` або надсиланні на статичному хостингу браузер може показати помилку після успішної HTML-валідації. Це не підтвердження входу, реєстрації чи створення товару.

Під час демонстрації використовуйте `student@example.com` і вигаданий пароль `TestOnly123`. Не вводьте справжні паролі. Для перегляду даних без надсилання використовуйте `FormData` нижче.

## Семантика, autocomplete і доступність

- Кожне поле має змістовні `id`, `name` і видимий `label` із відповідним `for`. `id` пов’язує поле з підписом, `name` визначає ключ даних.
- Email використовує `autocomplete=email`, поточний пароль — `current-password`, обидва нові паролі — `new-password`. Псевдонім використовує `nickname`, а не `name`: повне юридичне ім’я не запитується.
- Поля товару не мають стандартних профільних autocomplete tokens; штучні значення не задаються.
- `fieldset` і `legend` групують пов’язані дані, статус і кольори. Radio мають однаковий `name` й різні `value`.
- Підказки довжини, ціни та обмежень пов’язані через `aria-describedby`. Групові підказки пов’язані з `fieldset`.
- Кнопки надсилання мають явний `type=submit`. Скасування — звичайне посилання до каталогу. Reset не додано, щоб випадково не стирати введення.
- На кожній сторінці є skip link і один `main` із `tabindex=-1`, що дозволяє переходу встановити фокус. Додатних tabindex немає; порядок Tab визначає DOM.
- Нативний вигляд і фокус браузера збережено. Обов’язковість та підказки передаються словами, а не лише кольором.
- Згода з правилами не запитується: окремі правила сервісу в навчальному проєкті не визначені.

## Дані форми без Backend

Відкрийте сторінку форми, заповніть вигадані дані, натисніть F12 → Console та виконайте:

```js
const form = document.querySelector("form");
console.table([...new FormData(form).entries()]);
```

Це діагностична команда DevTools із завдання, а не JavaScript-файл проєкту. `FormData` сам не запускає валідацію й не надсилає запит. Для перевірки правил окремо виконайте `form.checkValidity()`.

Очікувані ключі: login — `email`, `password`; register — `displayName`, `email`, `password`, `passwordConfirmation`; product — `title`, `description`, `category`, `price`, `status`, і вибрані `finishes`. Непозначені checkbox та radio не потрапляють у дані. Кілька кольорів дають кілька пар `finishes=value`; `Object.fromEntries()` приховав би повторні ключі, тому використовуємо масив entries.

Приклад даних товару:

```text
title=LUME TABLE 01
description=Настільна лампа з регулюванням теплого світла.
category=light
price=129
status=published
finishes=ivory
finishes=ink
```
