# Практична №3: покроково у VS Code та GitHub

## 1. Підготувати папку

1. Розпакуйте `practical-03-lume.zip` через Провідник → правою кнопкою → «Видобути все».
2. Збережіть папку `practical-03-lume` у своєму каталозі практичної №3. Це продовження головної сторінки з практичної №2, а не інша тема.
3. У VS Code виберіть File → Open Folder і відкрийте саме папку, в якій лежать `index.html` та інші файли.
4. Ліворуч побачите дерево файлів. Натисніть `index.html`, щоб побачити код.
5. Після редагування зберігайте файл через Ctrl+S. Для перегляду README натисніть Ctrl+Shift+V.

## 2. Одразу створити репозиторій для третьої роботи

Рекомендований варіант — окремий `practical-03-lume`, який продовжує вихідні файли LUME. Так посилання другої практичної збереже її стан. Якщо викладач вимагає один репозиторій на всі практичні, використайте існуючий замість створення нового.

1. Увійдіть до свого акаунта GitHub у браузері.
2. Відкрийте https://github.com/new.
3. Repository name: `practical-03-lume`.
4. Description: `Практична робота №3 — HTML-форми магазину LUME`.
5. Виберіть Public, якщо робота має бути доступною викладачу без запрошення.
6. Не створюйте додатковий README: готовий файл уже є в папці. Натисніть Create repository.
7. На порожній сторінці репозиторію натисніть посилання uploading an existing file. Якщо репозиторій уже містить файли: Add file → Upload files.
8. Перетягніть **файли зсередини папки**, щоб `index.html` лежав у корені репозиторію. Не завантажуйте ZIP замість HTML-файлів.
9. Назва першого коміту: `Add LUME login, registration and product forms`.
10. Натисніть Commit changes. Відкрийте `login.html` і переконайтеся, що файл присутній.
11. Скопіюйте адресу репозиторію з браузера. Очікувана адреса для вашого акаунта — `https://github.com/aemuw/practical-03-lume`, але вона стане посиланням для здачі лише після фактичного створення.

Цей спосіб не вимагає термінала або встановленого Git. Для подальших змін можна редагувати у VS Code й знову завантажувати змінені файли через Upload files. Коміт — збережений набір змін із коротким поясненням.

Альтернатива з Git у VS Code: Source Control → Initialize Repository → створити коміт → Publish to GitHub. Вона вимагає встановленого Git та входу до GitHub. Не виконуйте обидва способи створення того самого репозиторію.

## 3. Відкрити сайт

1. У Провіднику відкрийте папку проєкту.
2. Двічі натисніть `index.html`; він відкриється в браузері.
3. Перевірте меню «Вхід», «Реєстрація», «Додати товар».
4. Сайт має стандартний вигляд браузера. Стилі не додано, бо робота зосереджена на HTML-формах і продовжує практичну №2 без CSS.

## 4. Розібрати форму входу

Відкрийте `login.html` у VS Code. Знайдіть `form`.

- `method=post` визначає спосіб передавання даних.
- `action=api/login` вказує майбутню адресу обробника.
- `label for=login-email` зв’язується з полем `id=login-email`.
- `name=email` задає назву даних, яку отримає сервер.
- `type=email` перевіряє базовий формат адреси.
- `required` забороняє порожнє поле.
- `autocomplete=current-password` повідомляє менеджеру паролів, що це вже наявний пароль.

У браузері натисніть «Увійти» з порожніми полями. Браузер має зупинити надсилання. Введіть неправильний email `wrong` та вигаданий пароль, повторіть. Потім використайте `student@example.com`.

Коректно заповнена форма спробує перейти до обробника, якого ще немає. Помилка після такого переходу очікувана. Натисніть «Назад». Для перевірки даних без переходу дивіться крок 7.

## 5. Розібрати реєстрацію

1. Відкрийте `register.html`.
2. Перевірте коротке ім’я з одного символу й пароль із трьох символів: браузер має відхилити надсилання.
3. Перевірте ім’я `Student` та пароль `TestOnly123`.
4. Спробуйте вставити ім’я довше 80 символів: браузер обмежить довжину введення.
5. Введіть різні паролі довжиною не менше восьми символів. HTML не визначить їхню невідповідність — це чесно зазначено в підказці та README.

`fieldset` групує поля, `legend` називає групу. `aria-describedby` пов’язує поле з поясненням. Зверніть увагу: пояснення видно ще до помилки.

## 6. Розібрати предметну форму

Відкрийте `product-form.html`. Це форма створення товару для майбутнього адміністратора LUME.

Заповніть приклад:

- Назва: `LUME TABLE 01`.
- Опис: `Настільна лампа з регулюванням теплого світла.`
- Категорія: «Світло».
- Ціна: `129`.
- Статус: «Опублікований».
- Кольори: Ivory та Ink.

Виконайте окремі негативні перевірки:

1. Назва `AB` — закоротка.
2. Опис `short` — закороткий.
3. Категорія «Оберіть категорію» — не обрана.
4. Ціна `0` — менша за дозволену.
5. Ціна `10000` — більша за дозволену.
6. Ціна `129.001` — не відповідає кроку одного цента.
7. Статус без вибору — required group не заповнено.

Для одного статусу використано radio; для кількох незалежних кольорів — checkbox; для списку категорій — select; для довгого опису — textarea. Посилання «Скасувати» повертає до каталогу.

## 7. Перевірити дані форми

1. Заповніть форму вигаданими даними, але не натискайте надсилання.
2. Натисніть F12 або Ctrl+Shift+I.
3. Виберіть вкладку Console.
4. Виконайте команду, передбачену завданням:

```js
const form = document.querySelector("form");
console.table([...new FormData(form).entries()]);
```

Якщо повторне оголошення `const form` викликає помилку, оновіть сторінку або виконайте одноразовий варіант:

```js
console.table([...new FormData(document.querySelector("form")).entries()]);
```

5. Звірте ключі з README. Два вибрані кольори — два рядки `finishes`. Непозначені кольори не з’являються.
6. Зробіть скриншот таблиці товару. Таблицю паролів для звіту краще не використовувати; достатньо предметної форми.

Ці команди працюють тільки в DevTools для перевірки. JavaScript до файлів сайту не підключається.

## 8. Перевірити доступність клавіатурою

1. Оновіть сторінку, натисніть Tab. Має виділитися «Перейти до основного вмісту».
2. Натисніть Enter: фокус перейде до основного вмісту, а наступний Tab — до наступного доступного елемента в ньому.
3. Пройдіть поля через Tab; назад — Shift+Tab.
4. На checkbox натисніть Space.
5. У групі radio вибирайте статус стрілками; Space активує сфокусований radio.
6. Клацніть підпис поля: текстове поле отримає фокус, checkbox перемкнеться.
7. У формі входу натисніть Enter у полі пароля: це має запустити надсилання з перевіркою.
8. Переконайтеся, що обов’язковість і правила зрозумілі з тексту.

## 9. Перевірити HTML

1. Відкрийте https://validator.w3.org/nu/.
2. Виберіть перевірку через File upload.
3. Завантажте `index.html` і натисніть Check.
4. Повторіть для `login.html`, `register.html`, `product-form.html`.
5. Збережіть скриншоти власної перевірки для звіту.

Підготовлені файли вже пройшли перевірку; після ваших змін перевірте їх ще раз.

## 10. Підготувати звіт

1. Відкрийте ваш шаблон звіту у Word, створіть копію для практичної №3.
2. Перенесіть матеріал із `REPORT-DRAFT.md` і використайте свій стиль рамок/основного напису.
3. Вкажіть правильну групу: у попередніх звітах зустрічаються П-325 та П-425, тому автоматично її не обираємо.
4. Додайте скриншоти трьох форм, приклад браузерної помилки, таблицю FormData та перевірку Nu.
5. Вставте фактичне посилання на створений репозиторій.
6. Експортуйте звіт у PDF.
7. Перед здачею відкрийте посилання GitHub у приватному вікні браузера: воно має показувати файли без входу, якщо ви обрали Public.

Скріншоти з підготовленої копії надано поряд з архівом. Перевірки скринридером не виконувались; базова семантика та клавіатурна поведінка перевірені.

## 11. За бажанням: посилання на сам сайт

GitHub-репозиторій — це сторінка з кодом, його вже можна здати. GitHub Pages додатково дозволяє відкривати HTML як сайт.

Після публікації репозиторію: Settings → Pages → Deploy from a branch → ваша основна гілка, зазвичай main → /(root) → Save. Дочекайтеся адреси, яку покаже GitHub. POST API на Pages не з’явиться: це статичний хостинг.
