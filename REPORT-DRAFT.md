# Чернетка звіту: практична робота №3

Це матеріал для перенесення у ваш шаблон Word, а не готовий оформлений звіт. Вкажіть актуальну групу, дату, фактичну адресу репозиторію та додайте скриншоти. Не стверджуйте, що особисто виконали перевірки, доки не повторите їх.

## Тема

Створення вебформ різного рівня складності.

## Мета

Навчитися створювати семантичні форми входу, реєстрації та введення предметних даних, застосовувати HTML-валідацію й autocomplete, пояснювати GET/POST та перевіряти клавіатурну доступність.

## Хід роботи

### 1. Продовження проєкту

За основу використано проєкт LUME з практичних №1–2 — магазин смарт-речей для дому. Головну сторінку доповнено навігацією до форм входу, реєстрації та створення товару. Проєкт реалізовано засобами HTML без CSS, JavaScript і Backend.

### 2. Форма входу

Створено сторінку login.html з полями email та поточного пароля, обов’язковістю required, autocomplete=email і current-password. Підписи label пов’язані з input через for/id. Додано кнопку «Увійти» та посилання на реєстрацію.

### 5. GET і POST

Форма пошуку використовує GET: запит потрапляє в URL, оскільки це операція отримання даних. Вхід, реєстрація й створення товару використовують POST. Маршрути api/login, api/register і api/products умовні; їх обробка ще не реалізована. POST не шифрує дані — для захисту передавання потрібний HTTPS.

## Висновок

Підготовлено три семантичні форми для проєкту LUME, налаштовано нативну HTML-валідацію, autocomplete, доступні підписи та групування. Визначено методи передавання й майбутні маршрути. Для подальшого розвитку потрібні серверна перевірка даних, безпечне зберігання паролів та перевірка прав адміністратора.

## Контрольні питання

1. **id і name:** id ідентифікує елемент у документі та пов’язує його з label; name задає ключ у даних форми.
2. **Placeholder і label:** placeholder зникає під час введення, тому не замінює постійний підпис.
3. **Checkbox, radio, select:** checkbox — незалежні варіанти; radio — один взаємовиключний варіант; select — вибір зі списку.
4. **fieldset і legend:** групують пов’язані поля й називають спільне питання.
5. **GET і POST:** GET — отримання/пошук із параметрами в URL; POST — передавання даних для обробки або зміни стану.
6. **POST і шифрування:** POST визначає спосіб запиту, а шифрування каналу забезпечує HTTPS.
7. **Autocomplete:** допомагає автозаповненню та менеджерам паролів зрозуміти призначення поля.
8. **HTML-валідація:** required, type, minlength, maxlength, min, max, step, pattern.
9. **Перевірка Backend:** клієнтські правила можна обійти, тому сервер повторно перевіряє отримані дані.
10. **Form data:** перевіряються через new FormData(form); поле повинно мати name й відповідати умовам включення в дані, наприклад checkbox має бути позначений.
